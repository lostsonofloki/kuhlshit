1. PRODUCT POSITIONING (AS EXPRESSED IN SHIPPED COPY & README)
--------------------------------------------------------------------------------
1.1 Core pitch
  - Self-described as a platform for discovering musicians, comedy acts, and
    community events, with a "dark-mode-only" industrial aesthetic inspired by
    Al's Spirits & Music (README.md).
  - index.html and seoDefaults frame the site as a home for musicians, painters,
    poets — Porch Talk, Closed on Sundays, PorchFest (Columbus MS), The Vault
    (index.html, src/constants/seoDefaults.js, public/manifest.json).

1.2 Named product surfaces (user-facing series)
  A) Closed on Sundays
     - Listening-room performances: short sets to camera; filmed for YouTube;
       in-person framing at Al's Spirits & Music (Reform, AL) with "bring a
       chair" copy (ClosedOnSundaysPage.jsx, seoDefaults, HomePage.jsx).
     - Hub schedule rows live as first-class objects inside porchfest.events
       with ids prefixed closed-on-sundays-YYYY-MM-DD (see section 7).

  B) Porch Talk
     - Interview / performance series; episodes loaded from a YouTube
       playlist via YouTube Data API v3 (PorchTalkPage.jsx).

  C) PorchFest
     - Primary festival record in data: PorchFest 2026, Munson & Brothers,
       Columbus MS, Apr 17–19 2026 — site copy treats the page as an archived
       post-event hub (PorchFestPage.jsx, data.json event id pf-001).

  D) The Vault
     - Archive of porchfest.events rendered newest-first with optional photo
       galleries and vaultLinks CTAs (VaultPage.jsx).

  E) Creators / Artists
     - Global directory at /artists; PorchFest lineup index at
       /porchfest/artists; per-creator profiles at both /artists/:id and
       /porchfest/artists/:id with redirect rules (ArtistDetailPage.jsx,
       App.jsx).

  F) Creator waitlist
     - Lead capture for future "Creator Studio" (WaitlistPage.jsx); optional
       remote POST to Web3Forms or custom endpoint (section 11).

1.3 Easter eggs & hidden routes
  - Louie dalmatian: random appearance on route change with probability 1/200;
    click navigates to /spotcheck (LouieEasterEgg.jsx).
  - Logo click counter: five consecutive clicks on header logo navigate to
    /retro (Header.jsx) — route defined outside App shell (main.jsx).

5. CONTENT MODEL — src/data/data.json
--------------------------------------------------------------------------------
5.1 Top-level keys observed
  - "artists": array of creator profiles (primary content).
  - "porchfest": { "events": [ ... ] } — BOTH the main multi-day festival AND
    ancillary dated series rows (Closed on Sundays shoots) share this array.
  - "metadata": informational counters and lastUpdated (may be inconsistent).

5.2 Artist objects — recurring fields (not every artist has every field)
  Identifiers & copy:
    - id (string slug), name, bio, location (optional), genre (optional)
    - imageUrl, thumbnailUrl (paths under /resources/...); cardImageFit optional
      (e.g. "contain" for SmartImage)
    - publishDate (ISO-like date string), featured (boolean)
    - creatorType (optional; drives layout on detail page)

  Links:
    - socialLinks: facebook, instagram, twitter (rendered as X in UI where
      applicable per CHANGELOG), youtube, spotify, appleMusic, website, tiktok
      (MusicianBody.jsx enumerates supported keys in Connect section).
    - musicLinks: spotify, appleMusic, youtube — CHANGELOG notes tidal and
      pandora supported for Listen row on MusicianBody.
    - links: e.g. bandsintown URL; separate bandsintown_slug string feeds widget
      (GigTracker.jsx).

  Media & promos:
    - videos[]: { title, videoId, thumbnail, url, source }
    - jingle.audioUrl optional (Fire Camino / AlsPackageStoreJingle)

  Live performances:
    - upcomingShows[]: sortDate (YYYY-MM-DD), when, title, where, supporting,
      notes, mapUrl, optional nested calendar object for explicit all-day ICS
      (see upcomingShowCalendar.js).

  Featured one-off show block:
    - featuredShow: eyebrow, title, billingLine, when, where, withArtistId,
      withArtistName, calendar { allDayStart, allDayEndExclusive, title, location,
      fileSlug, detailLine }, etc. (MusicianBody.jsx gates rendering on required
      fields).

  Legacy / optional JSON keys (present in some rows, not wired in MusicianBody):
    - README.md documents still { electricSet, interview, acousticCloser } and
      porchTalk objects; grep shows still/porchTalk still appear in data.json for
      at least one artist but MusicianBody.jsx contains no references to still or
      porchTalk — treat as legacy or future-use fields unless another component
      consumes them.

5.3 porchfest.events[] — two families of rows
  A) Main festival — example in repo: id "pf-001", name "PorchFest 2026",
     date/endDate, displayDate, pricing, schedule[], location { address, city,
     state, venue, mapUrl, website, socialLinks }, description, lineup[] (per-day
     artist strings or objects), imageUrl, lineupImageUrl, gallery { title,
     credit, photos[] }, infoUrl, vaultLinks optional.

  B) Closed on Sundays hub rows — ids like closed-on-sundays-2026-05-03,
     ISO date, location (Al's), description, lineup often empty array, vaultLinks
     { primary, secondary, tertiary optional } with React Router paths and labels.

  Discrimination logic (src/lib/closedOnSundayHubEvents.js):
    - isClosedOnSundayHubEvent: id starts with "closed-on-sundays-" AND date is
      strict YYYY-MM-DD.

5.4 Chicago timezone for hub scheduling
  - getChicagoDateKey and formatCosHubDateShort use America/Chicago for comparing
    hub dates to "today" and for display (closedOnSundayHubEvents.js).

6. SUPPORTING LIBRARIES (PROSE SUMMARIES)
--------------------------------------------------------------------------------
6.1 closedOnSundayHubEvents.js (src/lib/closedOnSundayHubEvents.js)
  - Filters and sorts Closed on Sundays hub events from porchfest.events.
  - Provides next/upcoming/past lists; formats short date labels in Chicago TZ.
  - artistIdFromCreatorProfilePath parses /porchfest/artists/x or /artists/x.
  - getCosHubEventCalendar merges hub row with artist.featuredShow.calendar when
    dates align; otherwise synthesizes all-day calendar metadata for Add To
    Calendar rows.

6.2 upcomingShowCalendar.js (src/lib/upcomingShowCalendar.js)
  - resolveCalendarForUpcomingShow: prefers explicit show.calendar all-day block;
    else if sortDate is YYYY-MM-DD and when line lacks wall-clock times,
    synthesizes all-day event to avoid misclassifying timed gigs.
  - addOneDayYmd: date arithmetic for exclusive end dates (ICS/Google all-day).

6.3 calendarLinks.js (src/lib/calendarLinks.js)
  - buildGoogleCalendarAllDayUrl: Google Calendar template URL per all-day spec.
  - buildAllDayICS: VCALENDAR body with PRODID kuhlshit.com.
  - downloadICSFile: client-side Blob download helper.

6.4 artistJsonLd.js (src/utils/artistJsonLd.js)
  - artistInFestivalLineup: compares normalized lineup entry names to artist.name.
  - buildArtistJsonLd: emits @graph with schema.org MusicGroup or Person (heuristic
    band name) or Person for non-musicians; includes sameAs from socialLinks,
    musicLinks, links values that look like https URLs; optional Event node tied
    to PorchFest dates/location with OfflineEventAttendanceMode.

6.5 siteSearch.js (src/lib/siteSearch.js)
  - searchSite(query, data): lowercase substring match across artist name,
    location, bio; events by name, city/state, description — powers header search.

6.6 useCachedFestivalData.js (src/hooks/useCachedFestivalData.js)
  - Attempts runtime fetch of bundled data.json URL; caches JSON in localStorage
    under kuhlshit:festival-data:v1; falls back to last cache then bundled import.
